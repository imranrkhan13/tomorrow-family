# Tomorrow: prescription reading demo

A cautious transcription prototype for fictional handwritten prescriptions, powered by Interfaze. Live: https://tomorrow-family.vercel.app/ . Source: https://github.com/imranrkhan13/tomorrow-family .

1. Upload only a fictional prescription (JPG, PNG, WebP, PDF or audio, up to 3 MB). Never upload patient data to this public prototype.
2. See possible medicine, dose, frequency and duration readings. Check each against the original. Unverified and missing details are red, and unreadable values are omitted rather than guessed. No medication reminders are created, even after checking; ask a pharmacist about unclear handwriting. This is not medical advice. Jev and Lev are not connected; a disabled, mock-tested server-side JevAPI text-check adapter is prepared but not wired into the public request path. It requires verified TypeSafe usage terms, budget and approval before activation. It never certifies medicine handwriting; do not treat source linking or the model output as cross-model confirmation.

The uploaded file is saved on this device in `tomorrow-intake-v1` IndexedDB. After picking a file, one explicit Send to Interfaze button starts extraction without an additional confirmation screen. Images and PDFs use one structured extraction request; audio uses two provider requests, transcription then field extraction from the transcript. The server caches the result by hashed input; lost responses trigger read-only lookup, not another provider call. An earlier general school-notice picture path had one real fictional Interfaze smoke test; the prescription-specific path, including PDF, has only mock-provider tests. Older cached general results remain labeled as such and are not retried. The user-reported PDF failure is unresolved. The server may return an older cached general extraction for identical input; those older fields are not promoted to a prescription reading and no paid call is repeated. Do not claim measured accuracy or Jev parity. The audio path has mock-provider tests only, not a real provider call. Audio transcription and field extraction are cached as separate stages; uncertain provider outcomes halt further requests and are never retried automatically. The displayed audio cost includes both stages when reported by the provider. The older mixed-document dashboard and the original family app remain in git history. Older browser data is not deleted, but the simple upload screen does not show previous text records.

To run: `npm ci && npm run verify && npm run dev`. A live API requires `INTERFAZE_API_KEY`, `FREE_CREDIT_CONFIRMED=true`, valid `TOKEN_CAP` and `CREDIT_CAP_USD`, Upstash Redis REST URL/token, and a long `HOUSEHOLD_ACCESS_CODE` in deployment. Do not put credentials in source control. Picture/PDF/audio intake and read-only lookup are public without an access code; the older extraction endpoint stays code-protected. Public use shares the same capped free-credit budget, which may be exhausted or halted by other visitors. Rate limiting is per browser device, not a reliable identity boundary. Do not upload real sensitive documents to this prototype.
